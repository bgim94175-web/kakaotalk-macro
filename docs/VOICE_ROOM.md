# 보이스룸 유지 — 지금까지 안 것과 실험 방법

목표: 방에 보이스룸을 열어 두고(48시간), 꺼지면 다시 연다.

## 1. 지금 아는 것

- 보이스룸은 오픈채팅 **그룹방**에서 **방장·부방장**만 연다. 열면 48시간 뒤 저절로 닫힌다(카카오 공지 기준).
- 남이 열면 봇에게 이런 푸시가 온다(`SENDER_TRACE_VOICE=1` 로 확인한 신호).
  - `MSG` chatLog.type **52** — "보이스룸을 시작합니다" 류의 알림
  - `CHGMETA` meta.type **16** — 보이스룸 정보(주소가 200자를 넘는다)
  - `CHGMETA` meta.type **17** — 참여 인원
- 여는 명령(LOCO)은 **아직 모른다**. 라이브러리(agent-messenger 2.38.0)에도 보이스룸 명령은 없다.

## 2. 실험실 (`SENDER_VOICE_LAB=1`)

봇 서버에 환경변수 `SENDER_VOICE_LAB=1` 을 주면 두 가지가 켜진다. 아무것도 저절로 열지 않는다.

### 모으기 — 남이 연 보이스룸의 신호 그대로 보기

```
GET /v1/bot/voice-seen?install_id=<방>      # x-sender-token 필요
```

다른 봇이 보이스룸을 켜고 끌 때의 `CHGMETA 16/17`·`MSG 52` 본문을 자르지 않고 최근 40개까지 담는다.
meta 16 의 `content` 가 핵심이다 — 보이스룸 주소·서버·방 번호가 여기 들어 있다.

### 두드리기 — 후보 명령 찾기

```
POST /v1/bot/voice-try   {"install_id": <방>}                      # 대조군 + 읽기 후보만 (안전)
POST /v1/bot/voice-try   {"install_id": <방>, "kinds": ["open"]}   # 여는 후보까지 (방에 실제로 열릴 수 있다)
POST /v1/bot/voice-try   {"install_id": <방>, "method": "SETMETA", "body": {...}}   # 한 개만 직접
```

첫 후보 `XXNOPE` 는 **일부러 없는 명령**이다. 그 응답 코드가 "없는 명령"의 코드이고,
그와 다른 코드를 돌려주는 명령은 서버에 **있는** 명령이다. 응답이 `statusCode 0` 이면 거기서 멈춘다.
결과의 `exists` 가 서버에 있는 명령 목록이다.

## 3. 다음 순서

1. 저 봇이 보이스룸을 켤 때 `voice-seen` 으로 meta 16 `content` 를 받는다.
2. `voice-try` 로 서버에 있는 명령을 추린다(먼저 읽기 후보, 그 다음 여는 후보).
3. 찾은 명령으로 유지 루프를 만든다: CHGMETA 16 이 "꺼짐"으로 오면 다시 연다(열기 간격·하루 한도 포함).
