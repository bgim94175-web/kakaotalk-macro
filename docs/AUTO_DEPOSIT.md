# 자동 입금확인 설정 — 개인 계좌 무인 키 발급

PG(카드결제) 없이, **은행 입금 알림을 기기가 서버로 전달하여** 키를 자동 발급하는 구성입니다.
사업자등록·심사·수수료 없이 즉시 적용할 수 있습니다.

```
구매자가 39,047원 입금
      ↓
은행이 내 폰에 알림/문자 보냄
      ↓
폰의 자동화 앱이 그 텍스트를 서버로 POST
      ↓
서버가 "39,047원" → 해당 주문 찾음 → 키 자동 발급
      ↓
구매자의 주문 페이지에 키가 바로 뜸
```

## 금액 뒷자리를 부여하는 이유

주문마다 금액에 **1~99원을 추가하여** 중복되지 않도록 처리합니다. 예: 39,000원 상품 → `39,047원`.

은행 알림 문자는 은행별 형식이 다르고 동명이인도 존재하므로 **이름 기반 매칭은 정확도가 확보되지 않습니다.**
금액을 고유하게 부여하면 **금액 하나로 주문이 특정**되므로 오작동이 발생하지 않습니다.
구매 페이지에는 정확히 39,047원을 입금해야 하며 뒷자리 47원이 주문 확인용이라는 안내가 크게 표시됩니다.

## 0. 서버 토큰 설정 (선행 작업)

Render → Environment → 추가:

| 변수 | 값 |
|---|---|
| `DEPOSIT_TOKEN` | 랜덤 32자 이상. 아래 명령으로 생성 |
| `DEPOSIT_AUTO_APPROVE` | `1` (기본값). 이 값을 유지한 상태로 **본인 계좌에 소액을 입금하여 테스트**하십시오. `0` 으로 설정하면 기록만 남기고 발급은 관리자가 수행하며, 구매 웹 문구도 그에 맞게 자동 변경됩니다 |

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

> **`DEPOSIT_TOKEN` 을 설정하지 않으면 입금 웹훅이 완전히 비활성화됩니다.** 토큰 없이 개방하면
> 임의의 사용자가 50,000원이 입금되었다고 서버에 위조 요청을 보내 키를 무료로 발급받을 수 있습니다. 절대 비워두지 마십시오.
> 이 토큰은 카카오톡·메모앱 등에 평문으로 보관하지 마십시오.

전송 주소:
```
https://kakaotalk-macro.onrender.com/api/deposit-hook?t=<DEPOSIT_TOKEN>
```

## 1. 안드로이드 — MacroDroid (안정성 최고, 권장)

은행 **푸시 알림**을 직접 수집합니다. 문자 알림 서비스(유료) 신청이 필요하지 않습니다.

1. Play 스토어에서 **MacroDroid** 설치 (무료 버전으로 충분합니다)
2. 권한: **알림 접근** 허용, **배터리 최적화 제외**
3. [매크로 추가] → 이름 `입금알림 전달`
4. **트리거** → `알림` → `알림 수신`
   - 애플리케이션: 사용 중인 은행 앱 선택 (카카오뱅크 / 토스 / KB스타뱅킹 …)
   - 포함할 텍스트: `입금`
5. **액션** → `연결` → `HTTP 요청`
   - 방식: **POST**
   - URL: `https://kakaotalk-macro.onrender.com/api/deposit-hook?t=여기에_DEPOSIT_TOKEN`
   - Content-Type: `application/json`
   - 본문:
     ```json
     {"text":"[notification_title] [notification_text]","source":"macrodroid"}
     ```
     `[notification_title]`, `[notification_text]` 는 MacroDroid 변수입니다.
     본문 입력창에서 `{x}` 버튼을 눌러 선택하여 삽입하십시오.
6. 저장 → 은행에서 소액(1원도 가능)을 본인 계좌로 입금하여 테스트
7. 관리자앱 **[주문] 탭 → [입금]** 에 원문이 수신되었는지 확인

**Tasker / Automate** 를 사용해도 됩니다. 구조는 동일합니다: `알림 수신` 트리거 → `HTTP POST`.

**Pushbullet** 로도 구성 가능하지만 기기 → Pushbullet 서버 → 자체 서버로 단계가 추가되고
Pushbullet API 를 폴링해야 하므로 속도와 복잡도에서 불리합니다. MacroDroid 를 권장합니다.

### 24시간 운영용 기기
기존 구형 안드로이드 기기를 충전기에 연결한 상태로 이 용도만 운영하면 됩니다(유심 없이 와이파이로 동작합니다).
배터리 최적화 제외 + 알림 접근 권한만 확인하십시오.

## 2. 아이폰 — 단축어 (문자 알림 필요)

**중요**: iOS 단축어에는 앱 알림 수신 트리거가 **존재하지 않습니다.** 은행 푸시 알림은 수집할 수 없습니다.
대신 「**메시지 받았을 때**」 트리거가 제공되며, 실행 전 확인을 비활성화하여 **완전 무인**으로 운영할 수 있습니다.

따라서 아이폰은 **은행 입금 문자(SMS) 알림 서비스**를 신청해야 합니다
(은행 앱 → 알림 설정 → 입출금 문자 통보. 통상 월 900원 내외이며, 은행에 따라 무료입니다).

1. **단축어** 앱 → [자동화] → [새로운 자동화]
2. **메시지** 선택
   - 보낸 사람: 은행 발신번호 (예: `1599-3333`) — 첫 입금 문자를 수신한 뒤 해당 번호를 입력하면 정확합니다
   - 또는 **메시지에 포함**: `입금`
   - **즉시 실행** 선택 + **실행 전에 묻기 끄기** → [묻지 않음] 확인
3. 동작 추가 → **URL의 콘텐츠 가져오기**
   - URL: `https://kakaotalk-macro.onrender.com/api/deposit-hook?t=여기에_DEPOSIT_TOKEN`
   - [화살표 펼치기] → 방식: **POST**
   - 본문: **JSON**
     - 키 `text` (텍스트) → 값에 **단축어 입력**(= 수신 메시지 내용) 변수 삽입
     - 키 `source` (텍스트) → 값 `shortcuts`
4. 저장 → 본인 계좌로 소액 입금하여 테스트

> 아이폰은 문자 서비스에 의존하므로, 문자가 지연되거나 수신되지 않으면 자동 확인이 동작하지 않습니다.
> **상시 운영하는 안드로이드 기기가 훨씬 안정적**이므로, 본격적으로 판매할 경우 구형 안드로이드 기기를 권장합니다.

## 3. 동작 확인 · 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 관리자앱 [주문] 탭 → [입금]에 데이터가 수신되지 않음 | 자동화 앱의 알림 접근 권한, 배터리 최적화 제외 확인. URL 의 `t=` 토큰 일치 여부 확인 |
| `503 DEPOSIT_TOKEN 미설정` | Render 에 `DEPOSIT_TOKEN` 이 설정되지 않았습니다 |
| `401` | `t=` 값이 서버 `DEPOSIT_TOKEN` 과 다릅니다 |
| 입금은 확인되었으나 `unmatched` | 구매자가 금액을 다르게 입금했습니다(뒷자리 누락). 관리자앱에서 **수동 매칭** |
| `ambiguous` | 동일 금액의 대기 주문이 2건 이상입니다. 관리자앱에서 수동 매칭 |
| `duplicate` | 동일 알림이 2회 전송되었습니다. 정상 동작입니다(중복 발급 차단) |
| 출금 알림까지 수신됨 | 서버가 `출금/결제` 키워드를 필터링하여 `ignored` 로 기록합니다. 트리거에 `입금` 포함 조건을 추가하면 정리됩니다 |
| 주문이 목록에서 사라짐 / 취소 상태 | 48시간 미입금 자동취소입니다(아래 3-1). 메모에 `입금이 없어서 자동 취소했어` 가 기록되며, **승인하면 복구됩니다** |

**미매칭·모호 건은 자동 승인되지 않습니다.** 관리자앱 [주문] 탭 → [입금]에서 원문을 확인한 후
대기 주문에 수동으로 연결하면 해당 시점에 키가 발급됩니다.

---

## 3-1. 48시간 미입금 주문 자동취소 (`ORDER_PENDING_TTL_MS`)

**주문이 사라진 사유는 대부분 이 항목입니다.** 입금 없이 48시간을 초과하여 방치된 `pending` 주문은
서버가 **자동으로 취소**합니다. 관리자가 삭제한 것이 아니며, 결함도 아닙니다.

필요한 이유: 자동 입금확인의 유일한 매칭 수단이 **금액 뒷자리 1~99원**인데, 인증 없이 생성 가능한
주문이 계속 누적되면 **뒷자리 99개가 고갈**됩니다. 그 이후 신규 주문은 전부 `suffix=0` + `needs_review`
로 처리되어 **자동 입금확인이 중단됩니다.** 자동취소는 해당 풀을 회수하는 장치입니다.

| 항목 | 실제 동작 |
|---|---|
| 기준 | 주문 `created_at` 이 `ORDER_PENDING_TTL_MS`(기본 `172800000` = **48시간**) 보다 오래된 `pending` 주문 |
| 실행 시점 | 주기 타이머가 아닙니다. **신규 주문 생성 시** 금액 뒷자리를 선택하기 직전에 1회 정리합니다. 따라서 주문이 일정 기간 없으면 48시간이 경과해도 `pending` 상태로 남을 수 있습니다 |
| 표시 | `status='canceled'` + `auto_canceled=TRUE`, 메모에 `입금이 없어서 자동 취소했어 (48시간 경과)` 가 기록됩니다 → **관리자가 직접 취소한 주문과 구분됩니다** |
| 서버 로그 | `[keys] 미입금으로 방치된 pending 주문 N건을 자동 취소했어` |

### 입금이 뒤늦게 확인된 경우 — 복구 가능

> **자동취소된 주문은 승인하면 그대로 복구됩니다.** 관리자앱 [주문] 탭에서 해당 주문을 **승인**하면
> 정상 주문과 동일하게 키가 발급됩니다(자동 입금확인 경로와 동일한 로직을 사용합니다).
> 반대로 **관리자가 직접 취소한 주문은 복구되지 않습니다**(`이미 취소된 주문이야` 로 거부) —
> 환불·취소 처리한 건이 입금 알림 하나로 복구되면 안 되므로 의도적으로 분리한 동작입니다.

운영 순서는 다음과 같이 처리하십시오.

1. 구매자가 이전 주문에 대해 입금을 완료했다고 문의 → [주문] 탭에서 해당 주문을 조회합니다(취소 상태로 존재합니다)
2. 메모에 `입금이 없어서 자동 취소했어` 가 기록되어 있으면 자동취소 건이므로 → **승인**하면 키가 발급됩니다
3. 금액 뒷자리가 이미 다른 주문에 재배정되었을 수 있으므로, 입금 금액이 불명확한 경우 [입금] 탭 원문을 함께 확인하십시오

기간을 변경하려면 `ORDER_PENDING_TTL_MS` 에 ms 값을 설정하십시오(24시간 = `86400000`).
기간을 짧게 설정하면 입금이 지연된 정상 구매자의 주문이 취소되므로(승인으로 복구는 가능합니다)
**48시간보다 단축할 이유는 거의 없습니다.**

## 4. 이 방식의 한계 (사전 확인 사항)

- **기기가 종료되거나 인터넷이 단절되면 해당 기간의 입금은 자동 확인되지 않습니다.** 이후 관리자앱에서 수동 승인하면 됩니다
  (주문은 `pending` 으로 유지됩니다. **48시간을 초과하면 자동취소되지만 승인 시 복구됩니다** — 3-1).
- **은행 알림 형식이 변경되면** 금액 파싱이 부정확해질 수 있습니다. 금액 숫자만 추출하는 방식이라 대부분의 변경은 수용되며,
  [입금] 탭에 원문이 그대로 보관되므로 문제 발생 시 즉시 확인할 수 있습니다.
- **세금·정산**: 개인 계좌로 대금을 반복 수령하면 사업자등록 의무가 발생할 수 있습니다.
  규모가 확대되면 사업자등록 + PG(토스페이먼츠·포트원) 가상계좌로 전환하는 것이 적절합니다.
  전환 시 `POST /api/deposit-hook` 대신 PG 웹훅을 수신하면 되며, 주문 승인 로직은 그대로 재사용됩니다.
- **환불**: 자동 발급 구조이므로 환불 요청 시 관리자앱에서 키를 **회수(revoke)** 한 후 계좌로 반환해야 합니다.
  구매 페이지에 환불 규정을 명시하면 분쟁이 감소합니다.
