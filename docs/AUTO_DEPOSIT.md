# 자동 입금확인 설정 — 개인 계좌로 무인 키 발급

PG(카드결제) 없이, **은행 입금 알림을 폰이 서버로 넘겨서** 키를 자동 발급한다.
사업자등록·심사·수수료 없이 바로 된다.

```
구매자가 39,047원 입금
      ↓
은행이 내 폰에 알림/문자 보냄
      ↓
폰의 자동화 앱이 그 텍스트를 서버로 POST
      ↓
서버가 "39,047원" → 해당 주문 찾음 → 키 자동 발급
      ↓
구매자의 주문 페이지에 키가 바로 뜸
```

## 왜 금액 뒷자리가 붙나

주문마다 금액에 **1~99원을 더해** 겹치지 않게 만든다. 예: 39,000원 상품 → `39,047원`.

은행 알림 문자는 은행마다 형식이 다르고 동명이인도 있어서 **이름으로 매칭하면 틀린다.**
금액을 고유하게 만들면 **금액 하나로 주문이 특정**돼서 오작동이 없다.
구매 페이지에 "정확히 39,047원을 보내줘 (뒷자리 47원은 주문 확인용)" 이라고 크게 표시된다.

## 0. 먼저 서버에 토큰 설정

Render → Environment → 추가:

| 변수 | 값 |
|---|---|
| `DEPOSIT_TOKEN` | 랜덤 32자 이상. 아래 명령으로 생성 |
| `DEPOSIT_AUTO_APPROVE` | `1` (자동 승인) — 처음엔 `0`으로 두고 기록만 보다가 익숙해지면 `1` |

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

> **`DEPOSIT_TOKEN`을 설정하지 않으면 입금 웹훅이 아예 꺼진다.** 토큰 없이 열어두면
> 누구나 "50,000원 입금됐다"고 서버에 거짓말해서 키를 공짜로 받을 수 있다. 절대 비워두지 마라.
> 이 토큰은 카톡·메모앱 등에 평문으로 남기지 마라.

보낼 주소:
```
https://kakaotalk-macro.onrender.com/api/deposit-hook?t=<DEPOSIT_TOKEN>
```

## 1. 안드로이드 — MacroDroid (가장 안정적, 추천)

은행 **푸시 알림**을 직접 잡는다. 문자 알림 서비스(유료)를 신청할 필요가 없다.

1. Play 스토어에서 **MacroDroid** 설치 (무료 버전으로 충분)
2. 권한: **알림 접근** 허용, **배터리 최적화 제외**
3. [매크로 추가] → 이름 `입금알림 전달`
4. **트리거** → `알림` → `알림 수신`
   - 애플리케이션: 쓰는 은행 앱 선택 (카카오뱅크 / 토스 / KB스타뱅킹 …)
   - 포함할 텍스트: `입금`
5. **액션** → `연결` → `HTTP 요청`
   - 방식: **POST**
   - URL: `https://kakaotalk-macro.onrender.com/api/deposit-hook?t=여기에_DEPOSIT_TOKEN`
   - Content-Type: `application/json`
   - 본문:
     ```json
     {"text":"[notification_title] [notification_text]","source":"macrodroid"}
     ```
     `[notification_title]`, `[notification_text]`는 MacroDroid 변수야.
     본문 입력창에서 `{x}` 버튼 눌러 골라 넣으면 돼.
6. 저장 → 은행에서 소액(1원도 됨)을 본인 계좌로 보내 테스트
7. 관리자앱 **[입금]** 탭에 원문이 들어왔는지 확인

**Tasker / Automate** 를 써도 된다. 구조는 같다: `알림 수신` 트리거 → `HTTP POST`.

**Pushbullet** 로도 되지만 폰 → Pushbullet 서버 → 내 서버로 한 단계를 더 거치고
Pushbullet API를 폴링해야 해서 느리고 복잡하다. MacroDroid가 낫다.

### 24시간 돌릴 폰
쓰던 구형 안드로이드 폰을 충전기에 꽂아두고 이것만 돌리면 된다(유심 없어도 와이파이로 동작).
배터리 최적화 제외 + 알림 접근 권한만 확인해라.

## 2. 아이폰 — 단축어 (문자 알림 필요)

**중요**: iOS 단축어에는 "앱 알림 받았을 때" 트리거가 **없다.** 은행 푸시 알림은 못 잡는다.
대신 「**메시지 받았을 때**」 트리거가 있고, 이건 '실행 전에 묻기'를 꺼서 **완전 무인**으로 돌릴 수 있다.

그래서 아이폰은 **은행 입금 문자(SMS) 알림 서비스**를 신청해야 한다
(은행 앱 → 알림 설정 → 입출금 문자 통보. 보통 월 900원 내외, 은행에 따라 무료).

1. **단축어** 앱 → [자동화] → [새로운 자동화]
2. **메시지** 선택
   - 보낸 사람: 은행 발신번호 (예: `1599-3333`) — 첫 입금 문자를 받은 뒤 그 번호를 넣으면 정확하다
   - 또는 **메시지에 포함**: `입금`
   - **즉시 실행** 선택 + **실행 전에 묻기 끄기** → [묻지 않음] 확인
3. 동작 추가 → **URL의 콘텐츠 가져오기**
   - URL: `https://kakaotalk-macro.onrender.com/api/deposit-hook?t=여기에_DEPOSIT_TOKEN`
   - [화살표 펼치기] → 방식: **POST**
   - 본문: **JSON**
     - 키 `text` (텍스트) → 값에 **단축어 입력**(= 받은 메시지 내용) 변수 삽입
     - 키 `source` (텍스트) → 값 `shortcuts`
4. 저장 → 본인 계좌로 소액 입금해서 테스트

> 아이폰은 문자 서비스에 의존하고, 문자가 늦거나 안 오면 자동 확인이 안 된다.
> **상시 켜둔 안드로이드 폰이 훨씬 안정적**이라, 판매를 본격적으로 할 거면 구형 안드로이드 폰을 권한다.

## 3. 동작 확인 · 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| 관리자앱 [입금] 탭에 아무것도 안 들어옴 | 자동화 앱의 알림 접근 권한, 배터리 최적화 제외 확인. URL의 `t=` 토큰이 맞는지 확인 |
| `503 DEPOSIT_TOKEN 미설정` | Render에 `DEPOSIT_TOKEN`을 안 넣었다 |
| `401` | `t=` 값이 서버 `DEPOSIT_TOKEN`과 다르다 |
| 입금은 들어왔는데 `unmatched` | 구매자가 금액을 다르게 보냈다(뒷자리 누락). 관리자앱에서 **수동 매칭** |
| `ambiguous` | 같은 금액의 대기 주문이 2개 이상. 관리자앱에서 수동 매칭 |
| `duplicate` | 같은 알림이 두 번 전송됨. 정상이다(중복 발급을 막은 것) |
| 출금 알림까지 들어옴 | 서버가 `출금/결제` 키워드를 걸러서 `ignored` 로 기록한다. 트리거에 `입금` 포함 조건을 넣으면 깔끔 |

**미매칭·모호 건은 자동 승인되지 않는다.** 관리자앱 [입금] 탭에서 원문을 보고
대기 주문에 수동으로 붙이면 그 자리에서 키가 발급된다.

---

## 4. 이 방식의 한계 (알고 쓰자)

- **폰이 꺼지거나 인터넷이 끊기면 그 사이 입금은 자동 확인이 안 된다.** 나중에 관리자앱에서 수동 승인하면 된다
  (주문은 `pending`으로 남아있다).
- **은행 알림 형식이 바뀌면** 금액 파싱이 틀릴 수 있다. 금액 숫자만 뽑는 방식이라 웬만해선 버티지만,
  [입금] 탭에 원문이 그대로 남으니 문제가 생기면 눈으로 바로 확인된다.
- **세금·정산**: 개인 계좌로 반복적으로 대금을 받으면 사업자등록 의무가 생길 수 있다.
  규모가 커지면 사업자등록 + PG(토스페이먼츠·포트원) 가상계좌로 넘어가는 게 맞다.
  그때는 `POST /api/deposit-hook` 대신 PG 웹훅을 받으면 되고, 주문 승인 로직은 그대로 재사용된다.
- **환불**: 자동 발급이라 환불 요청이 오면 관리자앱에서 키를 **회수(revoke)** 하고 계좌로 돌려줘야 한다.
  구매 페이지에 환불 규정을 적어두는 게 분쟁을 줄인다.
