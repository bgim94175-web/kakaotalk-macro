# 무단 사용 방지 — 실제로 뭘 막고, 뭘 못 막나

키 없이 APK만 뜯어서 쓰는 걸 막는 게 목표다. 솔직하게 정리한다.

## 핵심 원리

> 클라이언트(앱) 안의 검사는 **결국 패치될 수 있다.** 그래서 "검사를 늘리는" 방향으로는 이길 수 없다.
> 이 앱이 택한 방향은 **서버 없이는 앱이 쓸모없게 만드는 것**이다.

## 1단 — 설정 암호화 (가장 강한 방어) ⭐

앱을 쓸모있게 만드는 모든 값 — **발송할 메시지, 대상 방 목록, 트리거 규칙, 자동응답 문구, 봇 설정** —
은 평문으로 저장하지 않는다. `config_key`로 유도한 AES-256-GCM 키로 암호화해서 저장한다.

`config_key`는 **서버가 라이선스 검증 성공 응답에만** 실어 보내는 값이다.
서버 공식: `HMAC-SHA256(CONFIG_SECRET, 라이선스키 + "|" + 기기ID)`

앱 안 유도: `HKDF-SHA256(ikm=config_key, salt=기기ID, info="kakaoauto-cfg-v1", 32바이트)`

그래서 **라이선스 검증을 한 번도 통과하지 못한 기기는 자기가 저장한 설정조차 복호화할 수 없다.**
라이선스 검사 코드를 패치해서 "통과"로 바꿔도 `config_key`가 없으니 보낼 메시지가 없다.
앱은 켜지지만 아무 일도 하지 않는다. → **크랙의 이득이 0**

`config_key` 자체는 평문 저장 금지. AndroidKeyStore(`kakaoauto_cfg`, AES/GCM, 하드웨어 백업)로
감싸서 저장하므로 루팅하지 않은 기기에서는 파일을 복사해도 꺼낼 수 없다.

## 2단 — APK 서명 핀닝

앱이 자기 APK의 서명 인증서 SHA-256을 계산해 매 요청에 `app_sig`로 보낸다.
서버는 허용목록(`app_signatures` 테이블 + `ALLOWED_APP_SIGS` 환경변수)과 대조해 다르면 `bad_app_sig`로 거부한다.

APK를 수정하면 원래 서명이 깨져서 **반드시 재서명**해야 하고, 재서명하면 SHA-256이 달라진다.
→ 리패키징한 APK는 서버에 붙지 못한다.

### 한계 — 이 단은 "레포 Private" 에 걸려 있다 (의도된 트레이드오프)

지금 이 레포는 **서명키(`android/keystore/app.jks`)를 일부러 커밋해 두고 있고**,
`android/build.sh` 의 `KS_PASS` 기본값(`kakaomacro2026`)도 소스에 그대로 있다.
고정 키가 없으면 사용자가 앱을 지우지 않고 다음 버전을 덮어쓰기 설치할 수 없기 때문이다.

그 대가는 정확히 이거다:

> **레포를 읽을 수 있는 사람은 정품과 동일한 서명으로 개조 APK 를 만들 수 있다.**
> 그 APK 의 `app_sig` 는 `ALLOWED_APP_SIGS` / `docs/APP_SIGNATURE.txt` 값과 **같으므로**
> 서버가 통과시키고, `bad_sig` audit 도 남지 않는다. 기기에는 정품 위에 덮어쓰기로 깔린다.
> 즉 **이 사람에게는 2단이 존재하지 않는다.** 1단(설정 암호화)과 5단(온라인 필수)만 남는다.

그래서 지켜야 할 조건:

- **레포를 Private 으로 유지해라.** 2단이 의미를 갖는 전제다. 협업자 추가도 이 기준으로 판단해라.
- 비밀번호는 환경변수로 넘길 수 있다 — `build.sh` 는 `KS_PASS` 를 **먼저 보고**, 없을 때만
  기본값으로 떨어지면서 빌드 로그에 경고를 찍는다. CI 는 GitHub Secret `KEYSTORE_B64` + `KS_PASS` 를 쓴다.
- 공개 레포로 전환할 거면 **그 전에** 키스토어를 레포에서 빼고(`git rm --cached`) 두 값을 Secret 으로 옮겨라.
  히스토리에 남은 키까지 정리하거나 키를 교체할지도 같이 판단해야 한다
  (교체하면 사용자 전원이 앱을 지우고 다시 깔아야 한다 — DEPLOY.md 4장).
- 키스토어는 레포 밖에도 따로 백업해라. 잃으면 다음 버전에서 또 전원 재설치가 된다.

## 3단 — 변조 / 디버그 탐지

앱이 아래를 검사해서 `tamper` 문자열로 서버에 보고한다 (거부는 하지 않고 기록만 — 오탐으로 정상 사용자를 막으면 더 손해다).

- `FLAG_DEBUGGABLE` (디버그 빌드)
- `Debug.isDebuggerConnected()` (디버거 붙음)
- 설치 출처 이상 (`getInstallerPackageName`)
- 에뮬레이터 지표 (`Build.FINGERPRINT`, `MODEL`)
- APK 경로가 `/data/app` 밖

관리자앱 [기록] 탭에서 `tamper` 항목이 붉게 뜨므로, 누가 뜯고 있는지 눈으로 잡을 수 있다.

## 4단 — 1키 1기기 + 세션 회전

- 최초 검증 성공 시 `device_id`(ANDROID_ID)가 키에 **영구 고정**된다. 다른 기기는 `device_mismatch`로 무조건 거부.
- `device_fp`(하드웨어 지문: 제조사|모델|기기|보드|SDK|ABI 해시)가 바뀌면 `takeover`로 기록 — ANDROID_ID 복제 탐지용.
- **동시 사용 차단**: `/verify` 성공마다 새 `session` 토큰이 발급되고 이전 토큰은 무효가 된다.
  구 기기의 heartbeat는 `session_superseded`를 받고 **즉시 전체 기능이 잠긴다.**
  → ANDROID_ID를 복제해도 두 기기가 동시에 정상 동작할 수 없다.
- 기기 교체는 **관리자 초기화만** 가능하고, 초기화 횟수(`reset_count`)가 누적 표시되므로 남용이 보인다.

## 5단 — 온라인 필수 + 유예

- 최초 활성화는 반드시 온라인.
- 이후 기본 6시간(`recheck_ms`)마다 heartbeat. 연속 실패가 3일(`grace_ms`)을 넘으면 전체 기능 잠금.
  (지하철·비행기 등 일시적 오프라인은 3일까지 봐준다)
- **시계 되돌리기 방어**: 저장된 `last_ok`보다 현재 시각이 과거면 즉시 잠그고 재인증을 요구한다.
  (기기 날짜를 과거로 돌려 만료를 피하는 수법 차단)

## 6단 — 기능 게이트 단일화

모든 발송·봇 실행 경로는 `License.allowed(context, feature)` **한 지점만** 통과한다.
검사를 여기저기 흩뿌리지 않는다 — 우회 지점을 늘릴 뿐이다. 이 한 줄만 지키면 전체가 지켜진다.

## 못 막는 것 (솔직하게)

| 공격 | 막히나 | 이유 |
|---|---|---|
| APK 디컴파일해서 코드 읽기 | ❌ | 난독화를 안 했다. 막고 싶으면 R8/ProGuard를 붙여야 하는데, 이 앱은 Gradle 없이 빌드해서 현재 구조로는 추가 작업이 필요하다 |
| 라이선스 검사 코드 패치 | ⭕ 무의미 | 패치해도 `config_key`가 없어 설정 복호화 불가 → 보낼 메시지가 없다 |
| APK 재서명 후 배포 | ⭕ | 서명 SHA-256이 달라져 서버가 거부 |
| 키스토어가 유출된 상태에서 재서명 | ❌ | 서명 핀닝이 뚫린다. 키스토어는 레포에 커밋돼 있고 `build.sh` 의 기본 비번도 소스에 있으니, **레포 Private 유지가 이 방어의 전제**다 (위 2단 한계) |
| 정품 키를 산 사람이 친구와 돌려쓰기 | ⭕ | 1키 1기기 + 세션 회전으로 동시 사용 불가. 번갈아 쓰려면 매번 관리자 초기화를 요청해야 하고 횟수가 기록된다 |
| 루팅 기기에서 KeyStore 덤프 후 config_key 추출 | ❌ | 정품 키로 한 번 활성화한 기기라면 가능하다. 정품 사용자가 자기 설정을 복사하는 것이라 실질 피해는 없다 |
| 에뮬레이터 대량 생성 | ⭕ | 키 1개당 기기 1대이므로 키를 더 사야 한다 |

## 더 강하게 막으려면

**Play Integrity API** — 구글이 기기·앱 정상성을 서버에 보증해준다. 리패키징·에뮬레이터·루팅을 신뢰도 높게 잡는다.
단 **Google Play 스토어 배포가 전제**다. 지금처럼 APK를 직접 나눠주는 방식으로는 쓸 수 없다.

이 앱은 카톡 자동화라서 Play 스토어 정책(다른 앱 조작)에 걸릴 가능성이 높으니, 현실적으로는
**1단(설정 암호화) + 5단(온라인 필수)이 최종 방어선**이다. 그리고 그 두 개만으로도 실질적으로는 충분히 강하다.
