# 문구 규칙 (Tone & Voice)

구매 웹사이트 · K bot 패널 · 판매 관리 · 서버 응답 · K bot 방 메시지 · 운영 문서의 **모든 사용자 노출 문구**에 적용한다. 예외 없음.
새 문구를 쓰거나 고칠 때는 아래 **말투**와 **용어집**을 먼저 확인한다.

## 기준 — 2026-10 결정

**정중하고 간결한 합니다체.** 상태와 사실은 합니다체로 짧게 말하고, 읽는 사람에게 부탁할 때는 `~해 주세요`를 쓴다.
판매 페이지에서 `~하십시오`는 명령조로 딱딱하게 들려 **쓰지 않는다** (문장 점검 58번 결정, 이전 기준이던 `~하십시오`를 대체).
도구가 손님을 달래거나 꾸미지는 않는다. 무슨 일이 있었는지, 무엇을 하면 되는지만 말한다.

| 문장 종류 | 형태 | 예 |
|---|---|---|
| 본문 · 안내 · 상태 설명 | 합니다체 | `입금이 확인되었습니다.` `발송은 K bot 서버가 합니다.` |
| 읽는 사람에게 부탁 · 조치 안내 | `~해 주세요` | `[다시 시도]를 눌러 주세요.` `잠시 뒤 다시 시도해 주세요.` |
| 하지 말라는 부탁 | `~하지 마세요` | `비밀번호는 다른 사람과 공유하지 마세요.` |
| 할 수 있는 범위 (한도 · 선택 기능) | `~할 수 있습니다` | `카카오 계정은 3개까지 등록할 수 있습니다.` `이미지는 최대 5장까지 첨부할 수 있습니다.` |
| 늘 자동으로 일어나는 동작 | `~합니다` / `~됩니다` | `부방장으로 지정하면 1~2분 안에 자동으로 확인됩니다.` |
| 자주 묻는 질문의 질문 | `~나요?` / `~인가요?` | `어떤 기기에서 쓸 수 있나요?` `요금은 얼마인가요?` |
| 자주 묻는 질문의 답 | 합니다체 | `패널은 PC나 휴대폰 브라우저에서 열 수 있습니다.` |
| 라벨 · 요약 · 상태 칩 | 명사형 | `등록 필요` `접속 중` `부방장 지정 대기` |
| 버튼 | 동사형 또는 명사형, 2~5자 권장 | `저장` `주문하기` `문의하기` `다시 시도` |
| K bot 방 메시지 (카카오톡 방) | 짧은 대화체, 해요체 허용 | `「!도움」을 입력하면 명령어를 볼 수 있어요.` |

- `~할 수 있습니다`는 손님이 고르거나 한도 안에서 쓰는 일에만 쓴다. 늘 일어나는 동작에 붙이면 선택 사항처럼 읽힌다.
- 한도·범위를 `~까지 등록합니다`처럼 쓰면 의무처럼 읽힌다. `~까지 등록할 수 있습니다`로 쓴다.
- 운영 문서(`DEPLOY.md`, `docs/*.md`)도 같은 말투를 쓴다. 운영자에게 부탁하는 문장은 `~해 주세요`.

## 하지 말 것

| 금지 | 이유 · 대신 |
|---|---|
| 반말 (`~해`, `~야`, `~거든`, `~줘`, `어디야?`) | 이전 버전의 문제. 방 메시지·퀴즈 문제·힌트까지 전부 존댓말로 |
| `~하십시오` | 명령조. `~해 주세요` / `~하지 마세요`로 |
| 과도한 친절 (`~해볼게요`, `걱정 마세요`, `같이 확인해봐요`) | 도구가 사용자를 달랠 필요 없음 |
| 감탄사·이모지 장식 (`!`, `😊`, `✨`) | 상태 표시(`⚠`)만 허용. 방 명령어 앞의 `!`(`!도움`)는 장식이 아니므로 그대로 |
| 1인칭 주체 (`내가`, `제가 ~할게요`) | 행위자는 `K bot` · `K bot 서버` · `관리자`처럼 이름으로 쓴다 |
| 사과 (`죄송합니다`, `미안`) | 오류는 사과 대신 원인과 조치를 제시 |
| 불필요한 부연 | 한 문장으로 끝낼 것을 세 문장으로 늘리지 않는다. 손님에게 필요 없는 내부 정보(`5초 간격으로`, `기기 ID`)도 빼기 |
| 공문서 말투·번역투 (`하나의 ~에서`, `~에 대해`, `및`, `통상`, `불가합니다`, `~을 수행합니다`, `~을 가리킵니다`, `~가 제한됩니다`) | 일상어로: `한곳에서`, `~이 있으면`, `·`, `보통`, `할 수 없습니다`, `~합니다` |
| 개발용 표현 노출 (`렌더링`, `HTTP 500`, 영문 오류 원문, `프로세스`, `매칭`, `배정`, 환경변수 이름, 영문 상태값) | 손님 화면에서는 우리말 현상 + 조치로. 카카오 오류 코드는 `(오류 번호 -111)`처럼 괄호에만 |
| 무엇이 되는지 빠진 `적용` (`적용 완료`, `회원 계정에 적용됩니다`) | 실제 결과를 상품별로 쓴다: 매크로는 `바로 쓸 수 있습니다`, 방 관리봇·미니게임봇은 `K bot이 방에 들어갑니다`. 결과가 아직 아니면 `처리 중`·`처리 완료` (봇이 들어가기 전이나 부방장 지정 전에 `사용 가능`이라고 쓰지 않는다) |
| 자리표시 단어 노출 (`「대상」`, `누군가님`) | 이름을 모르면 `이 사람`, `참가자`처럼 문장을 바꾼다 |
| 분수 표기 (`경고 : 1/3회`) | `경고 1회 (3회가 되면 내보내요)` |
| 방에 욕설·금지어를 다시 올리기 | 경고 문구에 그 단어를 넣지 않는다 |

## 할 것

- **오류 문구는 [현상] + [조치]** 구조. 원인 추측은 확실할 때만. 조치는 `~해 주세요`.
  - `메시지를 보내지 못했습니다. 잠시 뒤 다시 시도해 주세요.`
- **누가 하는지 밝힌다.** 손님이 하는 일인지, K bot이 하는 일인지, 방장이 하는 일인지 주어가 빠지면 뜻이 뒤바뀐다.
  - `입장하면 바로 동작` → `K bot이 방에 들어가면 바로 사용`
- **버튼은 누른다.** `버튼을 선택하십시오`, `[다시 시도]를 실행하십시오` 대신 `[다시 시도]를 눌러 주세요`.
- **조사는 괄호·따옴표·코드 뒤에 붙여 쓰고 받침에 맞춘다.** `「!도움」으로`, `[다시 시도]를`, `「바람」은`, `서버 IP의`. (`!도움 으로`, `] 를`, `#12 을` 금지)
- **방 명령어는 문장 안에서 「」로 감싼다.** `「!포기」로 끝낸 뒤 시작해 주세요.`
- **숫자·단위는 명확하게** (`20~40분`, `최대 5장`, `하루 200회`). 가격·한도 숫자는 소스(`lib/pricing.js`, 서버 검사 값) 그대로 쓰고 문구를 다듬으면서 바꾸지 않는다.
- **사실만 쓴다.** 코드가 하지 않는 동작을 약속하지 않는다. 예: K bot은 올킥을 막지 않고 감지·기록만 하므로 `올킥 감지`라고 쓴다.
- **한 화면 안에서 한 대상은 한 이름으로 부른다.** 같은 것을 두세 이름으로 부르지 않는다 (아래 용어집).

## K bot 방 메시지

K bot이 카카오톡 오픈채팅방에 보내는 글(입장 안내, 경고, 미니게임 답 등)은 방 사람들이 채팅 중에 읽는다.

- **짧은 대화체.** 해요체(`~해요`, `~돼요`, `~해 주세요`)를 써도 된다. 반말은 쓰지 않는다.
- 방 사람들은 `계정`, `패널`, `회원`이 무엇인지 모른다. 봇은 닉네임으로(`「닉네임」`), 설정하는 사람은 `방장님` 또는 `관리자`로 쓴다.
- 알림 머리표는 기능 이름을 띄어 쓴 그대로: `[재입장 차단]` `[홍보 금지]` `[들낙 감지]`. (`[입장안내]`처럼 붙여 쓰지 않는다)
- **방 안내(입장·퇴장·프로필 변경·들낙·재입장 차단·홍보 금지)는 최대한 간단하게**(관리자 지정). 머리표 `[입장 안내]` `[퇴장 안내]` `[프로필 변경 감지]`,
  `이름 : @닉네임`(멘션 @ 는 글에 하나), 값 줄들, 맨 아래 줄은 시각 `오후 7:31` 하나(카카오톡은 글자 크기를 못 바꾸니 마지막 줄에 짧게).
  기호·접기([전체보기])·기록 목록(입장 횟수, 머문 시간, 예전 프로필, 누적 변경)은 안내에 쓰지 않는다 — 기록은 관리 화면에서 본다.
  프로필 변경은 `변경전 : ＠옛닉`(전각 ＠ — 멘션이 아니다) / `변경후 : @새닉`, 옾링이 바뀌면 `옾링 변경전 : …` / `옾링 변경후 : …`.
- 라벨 뒤에는 값만 둔다. `옾링 : 없음` (`옾링 : 찾지 못했습니다` 금지). 오픈프로필인데 옾링을 읽지 못했으면 `옾링 : 확인 못 함` — `없음`으로 바꾸지 않는다(없는 것과 못 읽은 것은 다르다).
- 오픈프로필 링크 라벨은 방 사람들이 쓰는 말 그대로 `옾링`이다(관리자 지정).
- 목록 답장(`!도움`, `!랭킹`)은 맨 위에 `[명령어]`, `[랭킹]`처럼 무슨 목록인지 적는다.

## 용어집

화면에 보이는 문구는 왼쪽 표기를 쓴다. 오른쪽 말은 쓰지 않는다.
코드 주석·변수명은 예전 말을 그대로 써도 된다 (개발자용이므로).

### 서비스 · 상품

| 화면 표기 | 쓰지 않는 말 | 비고 |
|---|---|---|
| **패널** (`K bot 패널`) | 콘솔, 웹 콘솔, 발송 콘솔 | 예외: Google 서비스 이름 `Google Cloud 콘솔`은 그대로 |
| **판매 관리** | 관리 콘솔 | `/manage` 관리자 화면 |
| **방 관리봇 · 미니게임봇** (또는 해당 봇 이름) | 방 상품, 방 단위로 쓴 `상품` | 두 봇을 함께 말할 때 `방 관리봇·미니게임봇` |
| **카카오톡 매크로** (줄여서 `매크로`) | 카톡 매크로 | 상품 이름. 서비스 이름은 `K bot` (`docs/BRAND.md`) |
| **K bot** | K bot 계정 (손님 화면 · 방 메시지에서) | 방에 들어가는 봇. 판매 관리·운영 문서에서 운영자 카카오 계정을 가리킬 때만 `K bot 계정` |
| **내 계정** (화면 이름) · **아이디** (로그인 맥락) | 회원 계정 (손님 화면에서) | 사이트 계정. `회원 계정`은 문서·코드 용어 |
| **카카오 계정** | 카카오계정 | 손님이 매크로용으로 등록한 자기 카카오 계정. 띄어 쓴다 |
| **설치** — 봇을 방에 넣는 동작에만: `봇 설치`, `설치할 방`, `봇을 설치한 방` | 기록·권리를 가리키는 명사 `설치` (`설치의 주인`, `다른 설치`, `결제된 설치`) | `설치의 주인` → `이 방의 회원`, `이 방에는 이미 다른 설치가 있습니다` → `이 방에는 이미 K bot이 있습니다` |

## 적용 범위

1. 구매 웹사이트 (`public/`) — 랜딩, 구매, 주문 조회, 내 계정, 로그인·회원가입, 문의
2. K bot 패널 (`public/panel.*`) — 로그인, 카카오 계정 등록, 매크로·봇 설정, 받은 갠톡
3. 판매 관리 (`public/manage.*`) — 주문 승인, 입금 확인, 회원, K bot 계정, 봇을 설치한 방
4. 서버 응답 중 사용자에게 보이는 문구 (`lib/`, `routes/`)
5. K bot 방 메시지 (`sender/`) — 위 「K bot 방 메시지」 규칙
6. 운영 문서 (`README.md`, `DEPLOY.md`, `docs/*.md`)

판매 관리와 운영 문서는 운영자가 읽으므로 `K bot 계정`, `회원`, 환경변수 이름처럼 운영에 필요한 말을 써도 된다. 말투 규칙은 같다.

## 코드 주석

주석은 **개발자용**이므로 친근한 설명체를 유지해도 된다. 단 반말은 통일해서 쓰고,
사용자 노출 문구와 혼동되지 않게 한다. 주석 때문에 문구 규칙이 흐려지면 안 된다.
