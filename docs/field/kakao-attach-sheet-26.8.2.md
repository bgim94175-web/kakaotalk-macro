# 실기기 화면 덤프 — 카카오톡 첨부 시트 (v26.8.2)

수집 환경: samsung SM-X520 · 안드로이드 16 (SDK 36) · 2304x1356 (density 1.75) · 카카오톡 26.8.2
수집 일시: 2026-09-28 17:38

**이것은 추측이 아니라 실기기에서 수집한 실제 뷰 트리다.** 셀렉터는 이 문서를 근거로 작성한다.

---

## 1. 이 화면이 무엇인가

**채팅방 내부의 첨부(+) 바텀시트**다. 공유 대상 선택 화면이 아니다.

근거:
- 루트가 `design_bottom_sheet` (Material 바텀시트)
- `rv_chat_tool` = 첨부 메뉴 목록 (카메라 · 사진 · 보이스룸 · 지도 · 파일 · 음성메시지 · 캡처)
- `rv_media` = 최근 사진 가로 스트립
- `전송` 버튼이 시트 안에 있다

즉 **공유 인텐트로 뜬 화면이 아니다.** 당시 카카오톡에 이미 떠 있던 화면을 접근성이 덤프한 것이다.
→ `ACTION_SEND_MULTIPLE` 로 공유창을 띄우는 시도는 여전히 실패했다는 뜻이다.

---

## 2. 확보된 view id (실측)

| 요소 | id | 클래스 | 비고 |
|---|---|---|---|
| 바텀시트 루트 | `design_bottom_sheet` | FrameLayout | |
| 시트 핸들 | `handle_container` | FrameLayout | `desc="전체화면 보기, 버튼"` |
| 첨부 메뉴 목록 | `rv_chat_tool` | RecyclerView | 스크롤 가능 |
| 최근 사진 스트립 | `rv_media` | RecyclerView | 스크롤 가능 (가로) |
| 섹션 제목 | `tv_title` | TextView | `text="최근 사진"` |
| 전송 버튼 | `btn_send` | Button | `desc="전송"` · 선택 전 `enabled=N` |
| 전송 버튼 글자 | `tv_send` | TextView | `text="전송"` |
| 사진 선택 순번 배지 | `tv_select_order` | TextView | 각 사진 썸네일의 자식 |
| 메뉴 항목 라벨 | `tv_label` | TextView | 사진 / 보이스룸 / 지도 / 파일 … |

## 3. 사진 썸네일 구조 (중요)

```
[Button] desc="사진, 9월 28일 오전 8:20" C=Y (220,764-402,946)
 [TextView] id=tv_select_order C=N (349,775-391,817)
```

- 각 사진은 **clickable Button**이고, `contentDescription` 이 `"사진, M월 D일 오전/오후 H:MM"` 형식이다.
- **촬영/저장 시각으로 특정 사진을 지목할 수 있다.** 앱이 보유한 이미지 URI 의 `DATE_TAKEN` /
  `DATE_ADDED` 를 같은 형식으로 포맷해 대조하면 정확한 사진을 고를 수 있다.
- 선택하면 `tv_select_order` 에 순번이 표시된다 → **선택 성공 여부를 검증할 수 있다.**
- 첫 항목은 `desc="카메라"` 로 사진이 아니다. 건너뛴다.

## 4. 전송 버튼 상태

```
[Button] desc="전송" id=btn_send enabled=N   ← 아무것도 선택 안 됨
```

`enabled` 가 선택 여부를 그대로 반영한다. **선택이 실제로 됐는지 판정하는 신뢰할 수 있는 신호다.**
`enabled=Y` 가 된 뒤에 눌러야 한다.

## 5. 첨부 메뉴 항목

`rv_chat_tool` 안의 항목들. 전부 `Button` + `desc` + 자식 `tv_label`.

```
사진 · 보이스룸 · 지도 · 파일 · 음성메시지 · 캡처
```

`앨범` 이 아니라 **`사진`** 이다. 기존 셀렉터 후보에 `앨범` 만 있었다면 못 찾는다.
항목 일부는 스크롤해야 보인다(`음성메시지`, `캡처` 는 `안보임` 상태였다).

## 6. 창 구성

```
창#4 type=APP active=Y focus=Y layer=0 pkg=com.kakao.talk 크기=(0,0-2304,1440)
```
카카오톡 창은 1개. 바텀시트는 별도 창이 아니라 같은 창 안의 뷰다.
→ `rootInActiveWindow` 로 접근 가능하다. `getWindows()` 순회가 필수는 아니다.

## 7. 이 덤프로 확정된 것

1. **`0␁` 접두사 버그가 실기기에서 재현됐다.**
   찾으려던 값: `"0🎆로블록스 계란을훔치다 계훔 킹피 던퀘…"` — 계정키가 이름에 섞여 있다.
2. **공유창(`ACTION_SEND_MULTIPLE`)은 여전히 뜨지 않는다.**
3. **채팅방 내부 첨부 흐름은 UI 구조가 전부 파악됐다.** 셀렉터를 추측할 필요가 없어졌다.
4. 타사 접근성 앱(GC 오토클리커)이 활성 상태였다.

## 8. 미확보 (추가 수집 필요)

- 채팅방 하단 **`+` (첨부) 버튼**의 view id — 시트가 이미 열린 상태를 덤프해서 안 잡혔다
- 채팅방 **메시지 입력창** id (기존 후보 `message_edit_text` 가 맞는지 미확인)
- `사진` 메뉴를 눌렀을 때 뜨는 **전체 갤러리 화면** 구조
- 공유 대상 선택 화면(뜬 적이 없어 구조 불명)
