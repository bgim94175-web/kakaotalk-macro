# 안드로이드 앱 빌드 안내

이 폴더에는 앱 두 개가 포함되어 있습니다.

| 폴더 | 패키지 | 결과물 | 용도 |
|---|---|---|---|
| `auto/` | `com.buseong.kakaoauto` | `out/KakaoAuto_v2.0.apk` | 사용자앱 (매크로 · 방관리봇 · 미니게임봇) |
| `admin/` | `com.buseong.kakaoadmin` | `out/KakaoAdmin_v2.0.apk` | 관리자앱 (키 · 주문 · 기록 · 설정) |

> ⚠️ **기존 v1.8 / v1.4 사용자에게 배포하기 전에 5장을 먼저 확인하십시오.**
> 서명키가 다르므로 **기존 앱을 삭제해야** v2.0 이 설치되며(설정이 삭제됩니다),
> `ALLOWED_APP_SIGS` 에 **값을 하나라도 설정하면 구버전 사용자 전원이 즉시 잠깁니다.**
> 이관 중에는 **비워두는 것**이 유일한 안전한 설정입니다 (→ 5-2).

Gradle 과 AndroidX 를 사용하지 않습니다. `aapt2 → javac → d8 → zipalign → apksigner` 를 직접 호출합니다.
외부 라이브러리 의존성은 **0개**입니다. (`org.json` 은 안드로이드 내장이므로 그대로 사용합니다)

---

## 1. 준비물

- **JDK 17 이상** (`javac`, `keytool` 이 PATH 에 포함되어야 합니다)
- **안드로이드 SDK** — 다음 두 항목만 필요합니다
  - `platforms;android-34`
  - `build-tools;34.0.0` (더 높은 버전이 설치되어 있으면 자동으로 최신 버전을 사용합니다)
- `zip` 명령

안드로이드 스튜디오가 설치되어 있으면 SDK 는 통상 다음 경로에 위치합니다.

```bash
# 리눅스
export ANDROID_HOME=$HOME/Android/Sdk
# 맥
export ANDROID_HOME=$HOME/Library/Android/sdk
```

스튜디오 없이 설치하려면 commandline-tools 만 받아 다음을 실행합니다.

```bash
sdkmanager "platforms;android-34" "build-tools;34.0.0"
```

`ANDROID_HOME` 을 설정하지 않아도 `ANDROID_SDK_ROOT`, `~/Android/Sdk`, `~/Library/Android/sdk`,
`/opt/android-sdk` 순서로 자동 탐색합니다. 탐색에 실패하면 조치 안내가 출력됩니다.

## 2. 빌드

```bash
cd android
chmod +x build.sh      # 처음 한 번만

./build.sh auto        # 사용자앱만
./build.sh admin       # 관리자앱만
./build.sh all         # 둘 다 (인자 없으면 이것과 같음)
```

결과물은 `android/out/` 에 생성됩니다.

```
android/out/KakaoAuto_v2.0.apk
android/out/KakaoAdmin_v2.0.apk
```

버전은 매니페스트에서 직접 읽어옵니다. 버전을 올리려면
`auto/AndroidManifest.xml` 의 `android:versionCode` / `android:versionName` 을 수정하면 파일명도 함께 변경됩니다.
(`versionCode` 는 **상향 시 반드시 숫자를 증가시켜야** 사용자가 덮어쓰기 업데이트를 수행할 수 있습니다)

### 깃허브에서 빌드

브랜치에 푸시하면 `.github/workflows/build-apk.yml` 이 실행되어 APK 두 개를 생성합니다.
저장소 → **Actions** 탭 → 해당 실행 → 하단 **Artifacts** 에서 `KakaoAuto`, `KakaoAdmin` 을 다운로드합니다.
수동 실행이 필요한 경우 Actions 탭에서 **Run workflow** 를 선택합니다.

## 3. 서명키 (중요) — 의도된 트레이드오프

`android/keystore/app.jks` 가 서명키입니다. **이 파일은 의도적으로 깃에 커밋되어 있으며**,
비밀번호 기본값도 `build.sh` 상단(`KS_PASS_DEFAULT`)에 평문으로 포함되어 있습니다.

> 서명키가 변경되면 이미 앱을 설치한 사용자는 업데이트를 설치할 수 없습니다
> ("앱이 설치되지 않았습니다" 오류). 고정 키를 확보하기 위해 저장소에 포함한 구성입니다.

대가는 다음과 같습니다.

> **저장소를 읽을 수 있는 사람은 정품과 동일한 서명으로 개조 APK 를 제작할 수 있습니다.**
> 해당 APK 의 `app_sig` 는 허용목록 값과 일치하므로 서버가 통과시키며, 정품 위에 덮어쓰기로도 설치됩니다.
> 즉 해당 사용자에게는 **서명 핀닝(4장)이 적용되지 않습니다.** → 따라서 **저장소를 Private 으로 유지하십시오.**
> 상세 내용은 `docs/ANTI_ABUSE.md` 2단을 확인하십시오.

- 키가 없으면 `build.sh` 가 자동으로 생성합니다 (RSA 2048 · 10000일 · alias `app` · CN `KakaoMacro`).
- **비밀번호는 환경변수 `KS_PASS` 를 우선 확인합니다.** 없는 경우에만 기본값으로 처리되며,
  기본값을 사용하면 빌드 로그에 `기본 키스토어 비밀번호를 쓰고 있어` 경고가 크게 기록됩니다.

```bash
KS_PASS="<진짜 비번>" ./build.sh all
```

- 깃에 키를 포함하지 않으려면(= 공개 저장소로 전환하려면) **GitHub Secret** 으로 전달하십시오.

```bash
base64 -w0 android/keystore/app.jks     # 맥은 base64 -i android/keystore/app.jks
```

출력값을 저장소 → **Settings → Secrets and variables → Actions → New repository secret** 에
이름 `KEYSTORE_B64` 로, 비밀번호를 `KS_PASS` 로 등록하면 CI 가 해당 값으로 서명합니다
(`.github/workflows/build-apk.yml` 이 두 변수를 build.sh 에 전달합니다). 로컬에서도 동일한 환경변수를 지정하면 됩니다.

```bash
KEYSTORE_B64="$(base64 -w0 keystore/app.jks)" KS_PASS="<진짜 비번>" ./build.sh all
```

### 3-1. 🔐 `app.jks` 를 절대 분실하지 마십시오

분실하면 **다음 버전에서 사용자 전원이 앱을 삭제하고 재설치해야 합니다** (현재 v1.8→v2.0 에서 발생한 상황).
저장소에 포함된 파일은 백업이 아닙니다. 최소 두 곳에 추가로 보관하십시오.

```bash
# 1) 파일 자체를 레포 밖 안전한 곳(암호 관리자 · 외장 디스크 · 개인 클라우드)에 복사
cp keystore/app.jks ~/안전한곳/kakaomacro-app.jks
# 2) base64 한 줄로 만들어 비밀 메모 / GitHub Secret(KEYSTORE_B64)에도 보관
base64 -w0 keystore/app.jks
```

비밀번호(`KS_PASS`)도 동일한 위치에 함께 기록하십시오. **키만 있고 비밀번호를 모르면 서명할 수 없습니다.**
복구 테스트도 1회 수행하십시오 — 백업이 확보되어 있으면 다음과 같이 복원됩니다.

```bash
KEYSTORE_B64="$(cat 백업한_base64.txt)" KS_PASS="<비번>" ./build.sh auto
# → 출력된 서명 hex 가 docs/APP_SIGNATURE_HISTORY.md 의 v2.0 값과 같으면 백업이 살아있는 것이다
#    (docs/APP_SIGNATURE.txt 와 비교하면 안 된다 — build.sh 가 방금 그 값으로 덮어써서 항상 같다)
```

### 3-2. 키스토어를 저장소에서 분리하는 절차 (방어 강화 시)

현재 상태(커밋된 키 + 소스에 포함된 기본 비밀번호)는 **저장소에 접근할 수 있는 사람에게는 서명 핀닝이 없는 것과 동일합니다.**
이를 해소하려면 키를 저장소에서 분리하고 **GitHub Secret 에만** 보관하면 됩니다. 대가는 키 백업 책임이 전적으로 담당자에게 이전된다는 점입니다.
`docs/ANTI_ABUSE.md` 2단의 트레이드오프를 먼저 확인한 뒤 판단하십시오.

```bash
cd /path/to/kakaotalk-macro

# 1) 키를 base64 한 줄로 만든다 (개행이 섞이면 CI 에서 디코드가 깨진다)
base64 -w0 android/keystore/app.jks > /tmp/ks.b64     # 맥: base64 -i android/keystore/app.jks > /tmp/ks.b64
wc -c /tmp/ks.b64                                     # 길이가 0 이 아닌지만 확인

# 2) GitHub Secret 2개 등록 (레포 → Settings → Secrets and variables → Actions → New repository secret)
#      KEYSTORE_B64 = /tmp/ks.b64 내용 전체
#      KS_PASS      = 키스토어 비밀번호 (기본값을 쓰고 있었다면 이 기회에 새 비번으로 바꿔라)
#    gh CLI 가 있으면:
gh secret set KEYSTORE_B64 < /tmp/ks.b64
gh secret set KS_PASS                                 # 프롬프트에 비번 입력

# 3) 로컬 백업을 먼저 확보한다 (레포에서 빼면 레포는 더 이상 백업이 아니다)
cp android/keystore/app.jks ~/안전한곳/kakaomacro-app.jks
#    권장 보관 위치: 암호 관리자(1Password·Bitwarden 등)의 파일 첨부 + 외장 디스크 1개.
#    base64 텍스트도 같이 넣고 KS_PASS 를 같은 항목에 적어둬라. 둘이 떨어지면 못 쓴다.
#    클라우드 드라이브에 평문으로 두지 마라 — 그건 레포에 두는 것과 위험이 같다.

# 4) 레포에서 추적 제거 + 무시 등록
git rm --cached android/keystore/app.jks
printf '\nandroid/keystore/*.jks\n' >> .gitignore
git add .gitignore && git commit -m "chore: 키스토어를 레포에서 빼고 Secret 으로 옮김"

# 5) CI 가 Secret 으로 서명하는지 확인 (Actions → 최신 실행 로그)
#    "KEYSTORE_B64 환경변수로 서명키를 복원한다" 가 찍히고
#    "기본 키스토어 비밀번호를 쓰고 있어" 경고가 안 찍혀야 한다.
#    빌드된 APK 의 서명 hex 가 docs/APP_SIGNATURE_HISTORY.md 의 v2.0 값과 같아야 한다.
```

- **4번 단계 이후에도 git 히스토리에는 키가 남아 있습니다.** 저장소를 공개로 전환하려면 히스토리 정리
  (`git filter-repo` 등)를 함께 수행하거나, 키가 유출된 것으로 간주하고 **키를 교체**해야 합니다.
  교체하면 **사용자 전원이 앱을 삭제하고 재설치해야 합니다**(현재 v1.8→v2.0 에서 발생한 상황) — DEPLOY.md 4장.
- 로컬 빌드 시에도 `KEYSTORE_B64` + `KS_PASS` 를 지정하면 됩니다(3장 예시). 지정하지 않으면 파일이 없으므로
  `build.sh` 가 **새 키를 생성하며**, 해당 APK 는 기존 사용자에게 덮어쓰기 설치가 불가합니다. 주의하십시오.

공개 저장소 전환 시 순서 요약: Secret 두 개 등록 → 로컬 백업 확인 → `git rm --cached android/keystore/app.jks`
→ `.gitignore` 에 `android/keystore/*.jks` 추가 → (히스토리에 남은 키 정리 또는 키 교체 여부 판단).

## 4. 서명 SHA-256 을 서버에 등록하는 절차 (리패키징 방지)

앱은 자체 APK 의 서명 SHA-256 을 계산하여 `/verify`, `/heartbeat`, `/entitlements` 요청마다
`app_sig` 로 함께 전송합니다. 서버는 허용목록과 대조하여, 제3자가 수정 후 재서명한 APK 를
`bad_app_sig` 로 거부합니다. **허용목록이 완전히 비어 있으면 그대로 통과시키므로(이관 유예)
새 APK 를 배포한 뒤에는 반드시 등록해야 합니다.**

### 4-1. 값 확인

빌드가 완료되면 스크립트가 마지막에 다음과 같이 출력합니다.

```
━━━ 서명 SHA-256 ━━━
  KakaoAuto_v2.0.apk
    콜론 있는 형식 : 33:ED:67:84:...
    서버 등록용 hex: 33ed6784cbea8bb3...
```

"**서버 등록용 hex**" (콜론 없는 소문자)가 서버에 등록할 값입니다.
동일한 값이 `docs/APP_SIGNATURE.txt` 에도 자동으로 기록됩니다 — **빌드할 때마다 현재 빌드 hex 한 줄로
덮어쓰므로(기계 판독용) 수동으로 수정하지 마십시오.**

> 📒 **알려진 서명 전체는 `docs/APP_SIGNATURE_HISTORY.md` 에 정리되어 있습니다.**
> `APP_SIGNATURE.txt` 는 이력을 보관하지 않으므로(덮어씁니다) 구버전 서명·CN·versionCode 는 히스토리 파일에서 확인하십시오.
> **빌드 검증도 히스토리 파일의 v2.0 행과 대조하십시오** — `APP_SIGNATURE.txt` 와 비교하는 것은
> build.sh 가 직전에 동일한 값을 기록하므로 **항상 통과하는 무의미한 검증입니다.**

별도로 확인하려면 다음을 실행합니다.

```bash
$ANDROID_HOME/build-tools/34.0.0/apksigner verify --print-certs out/KakaoAuto_v2.0.apk
```

사용자앱과 관리자앱은 동일한 키로 서명하므로 값도 동일합니다. 하나만 등록하면 됩니다.

### 4-2. 등록 — 방법 A: 환경변수 (권장)

Render → 해당 웹서비스 → **Environment** → `ALLOWED_APP_SIGS` 에 입력하고 저장 → 재배포.
값이 여러 개인 경우 쉼표로 연결합니다 (여러 세대의 v2.x 정품 서명을 동시에 허용할 때).

```
ALLOWED_APP_SIGS=33ed6784cbea8bb34eb9a4f08f1f13c845a588a8d7d14cb74915b70cc53730fa
```

> ⚠️ **기존 v1.8 사용자가 남아 있는 기간에는 이 변수에 어떤 값도 설정하지 마십시오 — 설정하는 즉시 전원이 잠깁니다.**
> **구버전 서명을 함께 등록해도 해제되지 않습니다.** v1.8 앱은 `app_sig` 를 전송하지 않으므로
> 대조할 값이 없고, 목록이 비어 있지 않으면 서버가 `bad_app_sig` 로 거부합니다. 상세 내용은 아래 5-2.

### 4-3. 등록 — 방법 B: 관리자앱

관리자앱 → **설정** → **앱서명 허용목록** → 추가.
이 경로는 DB(`app_signatures` 테이블)에 저장되어 재배포 없이 즉시 적용됩니다.

### 4-4. 구버전 차단 (선택)

새 APK 배포를 완료한 뒤 서버 환경변수 `MIN_APP_VERSION` 을 `20` 으로 상향하면
`versionCode` 가 그보다 낮은 구버전 앱은 업데이트 안내를 수신하고 차단됩니다.
기본값은 `0` (강제 업데이트 비활성)입니다.

**전원이 v2.0 으로 전환된 것을 확인한 뒤 상향하십시오.** 이관 중에 상향하면 v1.8 사용자가 즉시 차단됩니다.
차단 수준은 `bad_app_sig` 와 동일하지만(기능 전체 잠금), 사용자에게 표시되는 문구가
**앱 업데이트 안내**이므로 원인 파악이 즉시 가능하며 `0` 으로 되돌리면 즉시 복구됩니다.
따라서 **서명목록보다 이 값을 먼저 상향하여 구버전 잔존 여부를 확인하는** 순서를 권장합니다(5-2).

## 5. 기존 v1.8 / v1.4 사용자 이관 — **필수 확인**

기존에 배포한 APK 는 **다른 서명키**로 서명되어 있으며, 해당 키(.jks)는 보유하고 있지 않습니다 (APK 만 남아 있었습니다).
**원본 키가 없으므로 동일한 키로 서명하는 것은 불가능합니다.** 실측값:

| 앱 | 버전 | versionCode | CN | 서명 SHA-256 (hex) |
|---|---|---|---|---|
| KakaoAuto | v1.8 (기존) | 9 | KakaoAuto | `5b938482fa1d6eaff6a0cbbb23977d71ae0f65b8acd95a19c790d99c7f282467` |

### 5-1. ⚠️ 기존 앱을 먼저 삭제해야 설치됩니다

> # 기존 v1.8 / v1.4 가 설치된 기기는 v2.0 을 덮어쓸 수 없습니다.
> 서명자가 다르므로 설치가 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 로 실패합니다
> ("앱이 설치되지 않았습니다 / 패키지가 기존 패키지와 충돌합니다").
> **기존 앱을 먼저 삭제한 뒤** 새 APK 를 설치해야 합니다. 우회 방법은 없습니다.

**삭제하면 앱에 저장된 설정이 전부 삭제됩니다** — 발송 메시지, 대상 방 목록, 트리거·금지어,
자동응답 문구, 봇 설정, 첨부 이미지. 설정은 `config_key` 로 암호화되어 앱 데이터 내부에만 존재하므로
앱을 삭제하면 함께 삭제됩니다. 사용자에게 **사전에** 안내하십시오.

**라이선스 키는 삭제되지 않습니다** — 서버 DB 에 보관되므로 재설치 후 키만 다시 입력하면 기능이 그대로 복구됩니다.

#### 사용자 안내 문구

```
1. 기존 앱 삭제  (설정 → 앱 → 카톡 오토 → 제거)
   ※ 앱에 저장된 메시지·방 목록·트리거 설정은 삭제됩니다. 재설치 후 다시 입력해야 합니다.
   ※ 라이선스 키는 그대로 유지됩니다.
2. 새 APK 설치
3. 앱 실행 후 라이선스 키 재입력 → 인증
4. 권한 3개 재설정 (알림 접근 / 배터리 최적화 제외 / 이미지 사용 시 접근성)
5. 발송 메시지·대상 방·트리거 재설정
```

`device_id`(ANDROID_ID)는 앱 삭제로 변경되지 않으므로 통상 동일 기기에서 그대로 재활성화됩니다.
**1키 1기기** 제한으로 차단되는 경우 관리자앱 → 키 상세 → **기기초기화** 를 실행하면 됩니다.

### 5-2. 이관 단계별 서버 설정 (`ALLOWED_APP_SIGS` · `MIN_APP_VERSION`)

> 🔴 **`ALLOWED_APP_SIGS` 에 값을 설정하는 즉시 v1.8 사용자 전원이 `bad_app_sig` 로 잠깁니다.
> 구버전 서명 hex 를 함께 등록해도 동일합니다.**
>
> **v1.8 앱은 `app_sig` 필드를 전송하지 않습니다.** 서버 `routes/license.js` 의 `/verify` 는
> 목록이 비어 있지 않으면 `sigOk(app_sig)` 를 통과해야 하며, `sigOk` 는
> `s.length > 0 && 목록에 있음` 이므로 **빈 값을 무조건 거부합니다.**
> 즉 구버전 요청은 **대조 자체가 수행되지 않고** 바로 `bad_app_sig` 로 처리됩니다.
> 따라서 세 값을 모두 등록하는 방식은 **동작하지 않는 설정입니다.** 이관 중 안전한 값은 **빈 값 하나뿐입니다.**

| 단계 | 시점 | `ALLOWED_APP_SIGS` | `MIN_APP_VERSION` | 결과 |
|---|---|---|---|---|
| **1단계 — 이관 중** | v2.0 배포 시작 ~ 전원 전환 완료 전 | **비워둡니다** (빈 값 = 서명검사 건너뜀) | `0` | 구버전·신버전 모두 정상 동작 |
| **2단계 — 전환 완료 후** | 아래 방법으로 구버전 잔존이 없음을 확인한 뒤 | **v2.0 hex 하나만** | `20` | 구버전은 `update_required`, 리패키징은 `bad_app_sig` |

1단계 (아래 값 그대로 적용):

```
ALLOWED_APP_SIGS=
MIN_APP_VERSION=0
```

이 기간에는 리패키징 방어(2단)가 비활성 상태입니다. 다만 **1단(설정 암호화)과 5단(온라인 필수)** 이
유효하게 동작하므로 키 없이 앱을 사용하는 것은 여전히 차단됩니다 — `docs/ANTI_ABUSE.md`.

2단계 (전원 v2.0 전환 확인 후):

```
ALLOWED_APP_SIGS=33ed6784cbea8bb34eb9a4f08f1f13c845a588a8d7d14cb74915b70cc53730fa
MIN_APP_VERSION=20
```

#### 2단계 전환 시점 확인 — [기록] 탭으로는 불가

[기록] 탭은 **사고성 이벤트만** 기록합니다(`bad_sig`·`mismatch`·`tamper`·`expired`·`bad_admin_pw` 등).
**성공한 인증은 audit 에 기록되지 않으며**, 구버전은 `app_sig` 를 전송하지 않으므로
"구버전 서명으로 들어오는 요청이 중단되었다" 를 확인할 방법이 **존재하지 않습니다.** 실제로 관측 가능한 지표는 다음과 같습니다.

**(A) 키별 `app_sig` 기록 여부 — 주 지표**

`/verify` 성공 시 서버가 `licenses.app_sig` 를 `COALESCE(새값, 기존값)` 으로 갱신합니다.
v2.0 으로 1회 이상 인증하면 채워지며, **v1.8 만 사용하는 키는 계속 비어 있습니다**(전송하지 않으므로 덮어쓰이지도 않습니다).

- 관리자앱 **[키] 탭 → 키 상세**의 **"마지막 앱 서명"** 항목. 값이 없으면 해당 줄이 표시되지 않습니다
  → 아직 v2.0 으로 접속하지 않은 키입니다. 값이 v2.0 hex 이면 전환이 완료된 키입니다.
- 일괄 집계 방법은 `DEPLOY.md` 4-2 의 `curl /admin/list` 예시를 사용하십시오
  (`app_sig` 가 `null` 인 키 + 해당 키의 `last_seen` 을 함께 추출합니다).

**(B) `MIN_APP_VERSION` 선행 상향으로 확인 — 보조 수단 (무해하지 않음)**

`ALLOWED_APP_SIGS` 는 비워둔 상태로 `MIN_APP_VERSION=20` 만 먼저 상향합니다. 구버전이 잔존하는 경우
해당 사용자는 `update_required` 를 수신합니다.

**이 경우에도 기능이 차단되는 것은 `bad_app_sig` 와 동일합니다** — 앱은 서버 판정을 수신하면 라이선스 상태를 해제하고
`License.allowed()` 가 모두 거부합니다. 차이는 두 가지입니다.

- 표시 문구가 **앱 업데이트 안내**입니다(v2.0 앱 기준. 구버전 앱의 표시 문구는 v1.8 소스가 없어
  확인할 수 없습니다 — 최소한 서버가 전달하는 사유는 위조 앱 판정이 아니라 업데이트 요구로 변경됩니다)
- `MIN_APP_VERSION=0` 으로 되돌리면 **다음 재검증에서 즉시 복구됩니다**

또한 상향 직후 전원이 차단되지는 않습니다. `/verify` 는 `app_version` 을 전송하지 않은 요청도 `0 < 20` 으로
차단하지만, `/heartbeat`·`/entitlements` 는 **`app_version` 을 전송한 요청만** 검사합니다
(`routes/license.js` 의 `appCheck` → `v.appVer > 0`). 즉 해당 필드를 전송하지 않는 구버전은 이미 인증된
상태로는 계속 동작하며 **재인증 시점(재설치·기기변경·세션 복구)에 차단됩니다.**
→ 즉시 적용되는 스위치가 아니라 **점진적으로 드러나는 신호**입니다. (A)가 정리된 뒤에 상향하고, 며칠~몇 주간
문의가 없으면 그때 `ALLOWED_APP_SIGS` 에 v2.0 hex 를 설정하여 2단계를 완료하십시오.
(`update_required` 역시 서버 기록에 남지 않습니다. 사용자 문의를 통해 확인하는 방법입니다)

서명목록을 선행하여 설정하면 잔존 구버전 사용자는 **앱이 잠긴 상태로** 문의하게 됩니다.
적용 순서는 **(A) 확인 → (B) `MIN_APP_VERSION` → 며칠 대기 → `ALLOWED_APP_SIGS`** 입니다.

### 5-3. 🔐 `keystore/app.jks` 를 재분실하지 마십시오

> 금번 사안의 원인은 한 가지입니다 — **원본 서명키를 보관하지 못했습니다.**
> 이 키를 재분실하면 다음 버전에서 사용자 전원이 **다시** 앱을 삭제하고 설정을 재입력해야 합니다.

백업 방법은 3-1 을 확인하십시오 (저장소 외부 복사 + base64 보관 + `KS_PASS` 동시 기록 + 복구 테스트).
또한 `keystore/app.jks` 를 **변경하지 마십시오.** 변경은 재설치 사태를 한 번 더 발생시키는 것과 동일합니다.

## 6. 앱 설치 후 활성화해야 하는 권한 3개

설치만으로는 동작하지 않습니다. **아래 3개를 활성화해야 동작합니다.** 앱 [내정보] 탭에 해당 설정으로 이동하는 버튼이 있습니다.

### (1) 알림 접근 허용 — **필수**

카카오톡 알림을 읽어 방 이름 · 발신자 · 내용을 파싱하고, 알림에 포함된 답장창(RemoteInput)으로
메시지를 발송합니다. **이 권한이 비활성 상태이면 메시지를 발송할 수 없습니다.**

```
설정 → 알림 → 고급 설정 → 기기 및 앱 알림   (또는 "알림 접근")
  → "카톡 오토 · 알림 읽기" 켜기
```

제조사별 경로에 차이가 있습니다.
- 삼성: 설정 → 알림 → 고급 설정 → 기기 및 앱 알림
- 샤오미: 설정 → 앱 → 권한 → 알림 접근
- LG/기타: 설정 → 앱 → 특수 접근 → 알림 접근

> 활성화 후에도 동작하지 않으면 카카오톡 알림 자체가 비활성 상태인지 확인하십시오.
> 카카오톡 앱 내 **설정 → 알림 → 메시지 알림 ON**, 그리고 안드로이드 측에서도 카카오톡 알림이 허용되어 있어야 합니다.
> 알림을 무음으로 설정하는 것은 문제가 없습니다. 완전히 비활성화하면 동작하지 않습니다.

### (2) 접근성 — **이미지 전송 시에만 필요**

이미지 첨부(최대 5장) 발송은 알림 답장창으로 처리할 수 없습니다. 카카오톡 공유 화면을 대신 조작해야 합니다.
텍스트만 발송하는 경우 활성화하지 않아도 됩니다.

```
설정 → 접근성 → 설치된 앱 (또는 다운로드한 앱)
  → "카톡 오토 · 자동 조작" → 사용 켜기
```

카카오톡 화면만 읽습니다. 읽은 내용은 기기 외부로 전송되지 않습니다.

### (3) 배터리 최적화 제외 — **필수 수준**

미설정 시 화면을 끈 뒤 수 분 ~ 수십 분 내에 시스템이 앱을 절전 상태로 전환하여 주기 발송이 중단됩니다.

```
설정 → 배터리 → 배터리 사용량 최적화 → "카톡 오토" → 최적화하지 않음
```

- **삼성**: 설정 → 배터리 → 백그라운드 사용 제한 → **절전 모드에서 제외할 앱** 에 "카톡 오토" 추가.
  추가로 설정 → 디바이스 케어 → 배터리 → 백그라운드 사용 제한 → **사용하지 않는 앱 절전** 목록에서 제외하십시오.
- **샤오미 / 레드미**: 설정 → 앱 → 앱 관리 → 카톡 오토 → **자동 시작 허용** + 절전 정책 "제한 없음".
  최근 앱 화면에서 카톡 오토를 **잠금으로 고정**하면 안정성이 향상됩니다.
- **오포 / 비보 / 원플러스**: 설정 → 배터리 → 백그라운드 절전 → 카톡 오토 → 제한 없음.

### 그 외

- **알림 권한**(안드로이드 13 이상): 앱 실행 시 요청됩니다. 허용하십시오. 동작 상태를 알림으로 표시합니다.
- **사진 권한**: 이미지 첨부를 처음 선택할 때 요청됩니다. 이미지를 사용하지 않는 경우 거부해도 됩니다.
- **정확한 알람**: 매니페스트에 `USE_EXACT_ALARM` 이 포함되어 별도 허용이 필요하지 않습니다.
  "알람 및 리마인더" 권한을 요청하는 기기의 경우 허용하십시오.

## 7. 자주 발생하는 문제

| 증상 | 원인 / 조치 |
|---|---|
| `안드로이드 SDK 를 못 찾았어` | `export ANDROID_HOME=...` 로 SDK 경로를 지정 |
| `zip 명령이 없어` | `sudo apt-get install -y zip` |
| `javac 가 없어` | JDK 17 이상 설치 후 PATH 확인 |
| `자바 소스가 없어` | `auto/java/...` 에 `.java` 파일이 있는지 확인 |

| 업데이트 후 구버전 사용자 전원 잠김 | `ALLOWED_APP_SIGS` 에 값이 설정되어 있습니다(구버전 서명을 함께 등록한 경우에도 동일). **비워두십시오** — 5-2 |
| `기본 키스토어 비밀번호를 쓰고 있어` 경고 | `KS_PASS` 환경변수(또는 GitHub Secret)로 비밀번호를 전달하십시오 — 3장 |
| 빌드된 서명 hex 가 `APP_SIGNATURE_HISTORY.md` 와 불일치 | 키스토어가 변경되었습니다(백업 복원 실패 · 신규 생성). **배포하지 마십시오** — 그대로 배포하면 사용자가 앱을 다시 삭제해야 합니다. 3-1 백업부터 확인 |
| 앱은 실행되지만 메시지가 발송되지 않음 | (1) 알림 접근 허용, (2) 카카오톡 알림 ON, (3) 라이선스 활성화 여부를 [내정보] 탭에서 확인 |
| 화면을 끄면 중단됨 | 배터리 최적화 제외 (위 6-(3)) |
| 구버전 사용자만 `bad_app_sig` | `ALLOWED_APP_SIGS` 를 비워두십시오(5-2 1단계). v1.8 은 `app_sig` 를 전송하지 않으므로 목록에 어떤 값을 등록해도 통과하지 못합니다 |
| v2.0 인데 `bad_app_sig` | 해당 APK 서명이 허용목록과 다릅니다 = 다른 키로 서명된 빌드입니다. 4장 절차에 따라 현재 hex 를 등록하거나 정품 APK 를 재배포하십시오 |
| 관리자앱 **503 `admin_disabled`** | 앱 문제가 아닙니다. **서버 `ADMIN_PASSWORD` 가 비어 있거나 기본값(`change-me-now`)** 이어서 `/admin/*` 전체가 차단된 상태입니다 — `DEPLOY.md` 1장 |
| 관리자앱 **401** / **429** | 401 = 비밀번호 불일치. 429 = 분당 실패 한도(`ADMIN_FAIL_PER_MIN`, 기본 10) 초과로 IP 차단(기본 15분) — `DEPLOY.md` 7-1 |
